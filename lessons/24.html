01 · Что требуется уметь

Цель и критерий результата

Тема: Модульная аттестация II. Измеримая цель: Пройти выпуск и rollback тестовой версии.

Предварительные условия: тестовая среда или локальные синтетические данные, известная оболочка и подтверждённый рабочий каталог. Для внешних систем сначала сверяйте текущее состояние репозитория и официальную документацию.

Артефакт обучения: собственный прогноз → выполненная команда либо анализ кода → фактический вывод → независимая проверка → объяснение ограничений. На L3 требуется новая самостоятельная задача без подсказки.

02 · Механизмы и код

Техническое содержание

  1. Модульная аттестация II охватывает выпуск тестовой версии, наблюдение и восстановление предыдущего состояния по заранее известным артефактам.
  2. Approval без проверки digest и smoke результатов не является полноценным quality gate.
  3. Отчёт содержит release SHA, digest, baseline метрик, введённый сбой, конкретный trigger отката и post-rollback evidence.

Три конкретных примера

1. Заготовка release evidence

Пример: yaml
release:
  sha: "<candidate-sha>"
  digest: "sha256:<digest>"
  environment: "isolated-staging"
  smoke: "<actual-result>"
rollback:
  digest: "sha256:<previous>"
  verify: "<actual-result>"

Как интерпретировать: Значения заполняются только после реального теста; это не рабочая конфигурация deployment.

2. Проверяемые контрольные точки

Пример: text
B0: known-good response and artifact
B1: candidate response and metric snapshot
F1: injected reversible fault
R1: rollback + exact same smoke test

Как интерпретировать: Сравнение одной операции до и после не доказывает качество всей системы.

3. Безопасные команды для контекста

Пример: bash
git rev-parse HEAD
git status --short

Как интерпретировать: Выполняются в тестовой копии перед инцидентом. Реальный rollback без разрешения не запускать.

Каждый фрагмент показывает один проверяемый механизм. Блоки, содержащие несколько команд, изучайте и выполняйте по одной команде за раз. Учебные URL, имена и значения не являются утверждениями об актуальной конфигурации Ваших проектов.

02a · Углублённая теория и инженерные приёмы

Как устроен механизм: дополнительные примеры

Release + rollback как измеримая операция

Контрольная II проверяет не только успешный деплой, но и способность безопасно отменить плохую тестовую версию. До начала зафиксируйте текущие версии, ожидаемые метрики, результат проверки резервной копии и допустимый период деградации. Все эксперименты с флагами, отказами и rollback проводят на отдельном тестовом окружении.

Успех отката включает не только переключение версии, но и восстановление конечного пользовательского сценария. Логи, request IDs и контроли данных показывают, было ли восстановление полноценным.

T0: baseline / health=200 / synthetic-read=PASS
T1: candidate deployed / error-rate up
T2: rollback decision / digest identified
T3: old digest restored / smoke PASS
T4: report: impact, duration, root cause

# Чтение, до любой модификации
git status --short
docker compose ps --all
docker compose config -q

Приём: заранее определяйте «условие остановки эксперимента» (например, отказ тестового чтения). Ловушка: rollback после миграции без оценки совместимости БД. Проверка: разберите артефакты и повторите тестовое чтение/запись синтетических данных.

03 · Поиск причины

Разбор конкретного отказа

Наблюдаемый симптом

Новая версия дала нестабильный результат, требуется доказать, что возврат к предыдущей действительно помог.

Диагностическая развилка

Сопоставьте старый digest, исправившиеся метрики и тот же smoke-case; отделите rollback приложения от восстановления БД.

Ограничение вывода: устанавливайте только то, что действительно следует из измерения; альтернативные причины остаются гипотезами до проверки. Типичная ошибка: Выдавать за rollback повторный запуск без доказательства предыдущего digest.

04 · Показ → практика

Протокол безопасного эксперимента

  1. Назовите оболочку, текущую среду и область воздействия. В рабочих репозиториях сначала изучите состояние без изменения данных.
  2. По первому примеру сформулируйте прогноз: какой вывод подтвердит выбранный механизм, а какой его опровергнет?
  3. Выполните одну разрешённую команду в подходящей среде. Сохраните реальный stdout/stderr и exit code.
  4. Сравните результат с трактовкой под code block, затем выполните отдельную независимую проверку. При расхождении остановитесь и исследуйте ошибку.
Safety gate: примеры с изменением файлов, контейнеров, БД, прав, сети или инфраструктуры выполняются только в изолированном учебном стенде с синтетическими данными. При риске потери данных: сначала dry run/backup/restore plan и явное согласование. Не отправляйте пароли, токены и личные данные.
05 · Самостоятельная работа

Новая задача без готового решения

Самостоятельно проведите на отдельном учебном стенде release → smoke → обратимый сбой → rollback → повторную проверку.

Что сдавать

Выбранная Вами последовательность, прогноз, результат выполнения в синтетическом/читающем режиме, независимый контроль, указание возможного ложноположительного результата и безопасный способ восстановления (если было изменение).

06 · Контроль знаний

Вопросы, которые проверяют понимание

  1. Какие две разные сущности или стадии Вы должны различать в первом примере кода?
  2. Из симптома «Новая версия дала нестабильный результат, требуется доказать, что возврат к предыдущей действительно помог.» какие гипотезы возможны и какое наблюдение различит их?
  3. Почему выдавать за rollback повторный запуск без доказательства предыдущего digest — неверный диагностический вывод?
Показать критерий хорошего решения

Сопоставьте старый digest, исправившиеся метрики и тот же smoke-case; отделите rollback приложения от восстановления БД.

Нужны фактические доказательства, объяснение механизма, безопасная область воздействия и независимая проверка. Один зелёный тест не означает исправности всей системы.

L1 — воспроизводите готовое действие; L2 — решаете с опорой; L3 — сами выбираете способ для новой задачи, объясняете и проверяете; L4 — переносите навык и диагностируете риск/восстановление. Чтение учебника не присваивает уровень.
