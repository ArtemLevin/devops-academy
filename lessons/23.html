01 · Что требуется уметь

Цель и критерий результата

Тема: Публикация материалов. Измеримая цель: Разобрать deploy-student-static.yml.

Предварительные условия: тестовая среда или локальные синтетические данные, известная оболочка и подтверждённый рабочий каталог. Для внешних систем сначала сверяйте текущее состояние репозитория и официальную документацию.

Артефакт обучения: собственный прогноз → выполненная команда либо анализ кода → фактический вывод → независимая проверка → объяснение ограничений. На L3 требуется новая самостоятельная задача без подсказки.

02 · Механизмы и код

Техническое содержание

  1. Статический pipeline публикации состоит из build, проверки ссылок, публикации артефакта и независимого HTTP smoke-test после deployment.
  2. GitHub Pages/build workflows могут иметь специфические permissions и environment approvals; перед модификацией изучайте текущий deploy-student-static.yml.
  3. Операции с учениками проводятся исключительно на синтетическом примере: публичное размещение персональных данных недопустимо.

Три конкретных примера

1. Найти workflow в конкретном репозитории

Пример: bash
git ls-files ".github/workflows/*"
git grep -n "deploy-student-static" -- .github/workflows

Как интерпретировать: Запускайте только в клоне students-26-27; отсутствие совпадения требует проверки актуальных путей в репозитории.

2. Синтетический smoke после публикации

Пример: bash
curl -I --max-time 8 https://example.org/
# пример URL, не URL реального ученического сайта

Как интерпретировать: Успешный HEAD подтверждает только этот endpoint и доступность именно в момент проверки.

3. Контроль выпуска учебного HTML

Пример: text
source SHA  → validate links → build HTML
           → publish preview → GET /index.html
           → audit manifest + rollback reference

Как интерпретировать: Фактическая команда deployment должна соответствовать актуальному workflow, не переносите шаблон напрямую на рабочий сайт.

Каждый фрагмент показывает один проверяемый механизм. Блоки, содержащие несколько команд, изучайте и выполняйте по одной команде за раз. Учебные URL, имена и значения не являются утверждениями об актуальной конфигурации Ваших проектов.

02a · Углублённая теория и инженерные приёмы

Как устроен механизм: дополнительные примеры

Публикация статики и атомарность выдачи

Публикация учебного HTML/LaTeX/PDF состоит из генерации, проверки ссылок, вычисления контрольных сумм, загрузки и переключения опубликованной версии. Важно сохранить соответствие содержимого и манифеста: если HTML опубликован раньше зависимого изображения, пользователь может увидеть сломанную страницу. Версионированная директория и последующее переключение указателя уменьшают окно несогласованности.

GitHub Pages и иные CDN могут кешировать старые файлы; видимость коммита в GitHub не подтверждает мгновенную обновлённость сайта.

find public -type f -maxdepth 3 -print
sha256sum public/index.html
# Чтение локального учебного каталога перед публикацией

build v17 -> validate -> upload /releases/v17/
check /releases/v17/index.html
switch current -> v17
verify public URL + assets

Приём: используйте относительные ссылки для project Pages с префиксом /devops-academy/. Ловушка: абсолютная ссылка /assets/site.css может вести в корень домена и выдавать 404. Проверка: реально загрузите страницу и убедитесь, что все CSS/JS и изображения отвечают без 404.

03 · Поиск причины

Разбор конкретного отказа

Наблюдаемый симптом

Deployment отметил success, а одна ссылка в опубликованном пособии ведёт на 404.

Диагностическая развилка

Проверьте artifact version, относительный URL, case sensitivity и HTTP от публичного сайта; не перепубликуйте рабочие данные до выяснения причины.

Ограничение вывода: устанавливайте только то, что действительно следует из измерения; альтернативные причины остаются гипотезами до проверки. Типичная ошибка: Принимать зелёный workflow за доказательство доступности всех страниц.

04 · Показ → практика

Протокол безопасного эксперимента

  1. Назовите оболочку, текущую среду и область воздействия. В рабочих репозиториях сначала изучите состояние без изменения данных.
  2. По первому примеру сформулируйте прогноз: какой вывод подтвердит выбранный механизм, а какой его опровергнет?
  3. Выполните одну разрешённую команду в подходящей среде. Сохраните реальный stdout/stderr и exit code.
  4. Сравните результат с трактовкой под code block, затем выполните отдельную независимую проверку. При расхождении остановитесь и исследуйте ошибку.
Safety gate: примеры с изменением файлов, контейнеров, БД, прав, сети или инфраструктуры выполняются только в изолированном учебном стенде с синтетическими данными. При риске потери данных: сначала dry run/backup/restore plan и явное согласование. Не отправляйте пароли, токены и личные данные.
05 · Самостоятельная работа

Новая задача без готового решения

Для синтетического мини-сайта предложите link-check и post-deploy smoke с точными признаками успешности.

Что сдавать

Выбранная Вами последовательность, прогноз, результат выполнения в синтетическом/читающем режиме, независимый контроль, указание возможного ложноположительного результата и безопасный способ восстановления (если было изменение).

06 · Контроль знаний

Вопросы, которые проверяют понимание

  1. Какие две разные сущности или стадии Вы должны различать в первом примере кода?
  2. Из симптома «Deployment отметил success, а одна ссылка в опубликованном пособии ведёт на 404.» какие гипотезы возможны и какое наблюдение различит их?
  3. Почему принимать зелёный workflow за доказательство доступности всех страниц — неверный диагностический вывод?
Показать критерий хорошего решения

Проверьте artifact version, относительный URL, case sensitivity и HTTP от публичного сайта; не перепубликуйте рабочие данные до выяснения причины.

Нужны фактические доказательства, объяснение механизма, безопасная область воздействия и независимая проверка. Один зелёный тест не означает исправности всей системы.

L1 — воспроизводите готовое действие; L2 — решаете с опорой; L3 — сами выбираете способ для новой задачи, объясняете и проверяете; L4 — переносите навык и диагностируете риск/восстановление. Чтение учебника не присваивает уровень.
