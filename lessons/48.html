01 · Что требуется уметь

Цель и критерий результата

Тема: Защита. Измеримая цель: Решить новый инцидент без подсказок.

Предварительные условия: тестовая среда или локальные синтетические данные, известная оболочка и подтверждённый рабочий каталог. Для внешних систем сначала сверяйте текущее состояние репозитория и официальную документацию.

Артефакт обучения: собственный прогноз → выполненная команда либо анализ кода → фактический вывод → независимая проверка → объяснение ограничений. На L3 требуется новая самостоятельная задача без подсказки.

02 · Механизмы и код

Техническое содержание

  1. Итоговая защита — новая неисправность, для которой Вы выбираете команды и порядок проверок без подсказок преподавателя.
  2. Качественная диагностика связывает симптом → альтернативные гипотезы → различающий эксперимент → установленную причину → безопасное исправление.
  3. Успех оценивают по объективному тесту после исправления, пределам вывода, плану rollback/restore и переносимости метода на другие проекты.

Три конкретных примера

1. Новый учебный инцидент (не готовое решение)

Пример: text
User submits publication → HTTP 202
Queue depth grows → PDF not published
API/worker/db availability unknown
Constraint: synthetic data, isolated stack

Как интерпретировать: Выберите минимальные проверки самостоятельно: готовая последовательность здесь намеренно не приведена.

2. Структура аттестационного отчёта

Пример: yaml
incident_id: final-demo
hypotheses: []
measurements: []
root_cause: unconfirmed
change_approval: pending
recovery_test: pending
limits: []

Как интерпретировать: Передайте реальные ссылки на вывод команд, логи без секретов и итоговый smoke; не подставляйте вымышленные значения.

3. Минимальный контекст для объективных проверок

Пример: bash
git rev-parse HEAD
ps -eo pid,ppid,stat,comm | head -20

Как интерпретировать: Эти команды фиксируют часть контекста, но не заменяют диагностику неизвестной неисправности.

Каждый фрагмент показывает один проверяемый механизм. Блоки, содержащие несколько команд, изучайте и выполняйте по одной команде за раз. Учебные URL, имена и значения не являются утверждениями об актуальной конфигурации Ваших проектов.

02a · Углублённая теория и инженерные приёмы

Как устроен механизм: дополнительные примеры

Защита проверяет перенос инженерного мышления

Итоговая задача не должна повторять уже разобранный пример. Экзаменуемый самостоятельно формирует гипотезы, выбирает безопасные наблюдения, различает симптомы и причины и обосновывает решение об изменении системы. Условия оценки: факты до изменения, явные риски, шаги проверки, независимое доказательство результата и план отката.

L4 демонстрируется при переносе метода в новый контекст с диагностикой отказа и оценкой риска. Успех исполняемого теста сам по себе не автоматически означает L3/L4; требуется объяснение и объективные свидетельства выполнения учеником.

Сценарий: 202 Accepted, но PDF не появляется
Первое наблюдение: request ID и job state
Далее: outbox -> broker -> worker -> artifact storage
План: read-only evidence до коррекции
Критерий: синтетический PDF доступен + инварианты

Evaluation:
1. Correct model of failure domain
2. Minimal-risk action sequence
3. Independent verification
4. Recovery / rollback evidence
5. Transfer to unfamiliar case

Приём: на защите вслух прогнозируйте результат команды до запуска. Ловушка: перечислять популярные команды без причинной модели. Проверка: объясните, какие наблюдения могли бы опровергнуть Вашу главную гипотезу.

03 · Поиск причины

Разбор конкретного отказа

Наблюдаемый симптом

После публикации учебного задания пользователю пришёл 202, но PDF отсутствует; одновременно CPU не загружен.

Диагностическая развилка

Отделите отказ очереди, worker и хранилища; получите реальные доказательства, затем выберите безопасное вмешательство и проверку.

Ограничение вывода: устанавливайте только то, что действительно следует из измерения; альтернативные причины остаются гипотезами до проверки. Типичная ошибка: Подгонять объяснение под успех и пропускать независимую проверку.

04 · Показ → практика

Протокол безопасного эксперимента

  1. Назовите оболочку, текущую среду и область воздействия. В рабочих репозиториях сначала изучите состояние без изменения данных.
  2. По первому примеру сформулируйте прогноз: какой вывод подтвердит выбранный механизм, а какой его опровергнет?
  3. Выполните одну разрешённую команду в подходящей среде. Сохраните реальный stdout/stderr и exit code.
  4. Сравните результат с трактовкой под code block, затем выполните отдельную независимую проверку. При расхождении остановитесь и исследуйте ошибку.
Safety gate: примеры с изменением файлов, контейнеров, БД, прав, сети или инфраструктуры выполняются только в изолированном учебном стенде с синтетическими данными. При риске потери данных: сначала dry run/backup/restore plan и явное согласование. Не отправляйте пароли, токены и личные данные.
05 · Самостоятельная работа

Новая задача без готового решения

Решите неизвестный сбой в изолированном стенде без указания команд преподавателем, предъявив baseline, результат, rollback и ограничения.

Что сдавать

Выбранная Вами последовательность, прогноз, результат выполнения в синтетическом/читающем режиме, независимый контроль, указание возможного ложноположительного результата и безопасный способ восстановления (если было изменение).

06 · Контроль знаний

Вопросы, которые проверяют понимание

  1. Какие две разные сущности или стадии Вы должны различать в первом примере кода?
  2. Из симптома «После публикации учебного задания пользователю пришёл 202, но PDF отсутствует; одновременно CPU не загружен.» какие гипотезы возможны и какое наблюдение различит их?
  3. Почему подгонять объяснение под успех и пропускать независимую проверку — неверный диагностический вывод?
Показать критерий хорошего решения

Отделите отказ очереди, worker и хранилища; получите реальные доказательства, затем выберите безопасное вмешательство и проверку.

Нужны фактические доказательства, объяснение механизма, безопасная область воздействия и независимая проверка. Один зелёный тест не означает исправности всей системы.

L1 — воспроизводите готовое действие; L2 — решаете с опорой; L3 — сами выбираете способ для новой задачи, объясняете и проверяете; L4 — переносите навык и диагностируете риск/восстановление. Чтение учебника не присваивает уровень.
