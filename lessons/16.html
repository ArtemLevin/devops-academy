01 · Что требуется уметь

Цель и критерий результата

Тема: Сборка LaTeX/HTML. Измеримая цель: Составить шаги проверки синтетического пособия.

Предварительные условия: тестовая среда или локальные синтетические данные, известная оболочка и подтверждённый рабочий каталог. Для внешних систем сначала сверяйте текущее состояние репозитория и официальную документацию.

Артефакт обучения: собственный прогноз → выполненная команда либо анализ кода → фактический вывод → независимая проверка → объяснение ограничений. На L3 требуется новая самостоятельная задача без подсказки.

02 · Механизмы и код

Техническое содержание

  1. В конвейере публикации LaTeX → PDF и HTML → сайт каждый шаг имеет вход, выход и проверяемый контракт. Изменение одного исходника может влиять на несколько сборок.
  2. LaTeX-компиляция может требовать нескольких проходов для ссылок; warnings, undefined references и отсутствие PDF — разные состояния.
  3. Сборку материалов учеников выполняют только на синтетических данных; артефакт фиксируют с checksum и SHA исходников.

Три конкретных примера

1. Минимальное синтетическое пособие

Пример: latex
\documentclass{article}
\usepackage[utf8]{inputenc}
\begin{document}
Hello, $E=mc^2$.
\end{document}

Как интерпретировать: UTF-8 исходник, одна формула и PDF на выходе. Реальный список пакетов зависит от установленного TeX-дистрибутива.

2. Проверить наличие сборщика

Пример: bash
command -v pdflatex
command -v latexmk

Как интерпретировать: Если команда отсутствует, сначала документируйте окружение; не устанавливайте пакеты вслепую.

3. Карта этапов

Пример: text
source.tex → TeX compile → out.pdf → PDF validation
index.html  → static check → preview → link check
SHA(source) + SHA(artifact) → evidence

Как интерпретировать: Каждый результат проверяется отдельно: file exists, видимый контент и отсутствующие ссылки.

Каждый фрагмент показывает один проверяемый механизм. Блоки, содержащие несколько команд, изучайте и выполняйте по одной команде за раз. Учебные URL, имена и значения не являются утверждениями об актуальной конфигурации Ваших проектов.

02a · Углублённая теория и инженерные приёмы

Как устроен механизм: дополнительные примеры

Конвейер документов как компилятор

Публикация учебных материалов — цепочка трансформаций исходник → проверка → сборка → HTML/PDF → публикация. Каждая стадия имеет вход, выход, статус и хеш. LaTeX может корректно компилироваться, сохраняя неверную математическую формулу; поэтому содержательные и технические проверки нужны отдельно.

При генерации HTML обрабатывайте пользовательский текст как данные: экранируйте <, & и кавычки при включении в атрибуты. В примерах используйте синтетические имена и задачи.

\documentclass{article}
\usepackage{amsmath}
\begin{document}
\[x^2 - 5x + 6 = (x-2)(x-3)\]
\end{document}

from html import escape
lesson_title = "Синтетический урок <№1>"
print(f"<h1>{escape(lesson_title)}</h1>")

Приём: сохраняйте manifest с input SHA256, версией toolchain и output SHA256. Ловушка: exit 0 компилятора не доказывает, что шрифты встроены и формулы визуально корректны. Проверка: дополните сборку просмотром итогового PDF/HTML и проверкой ссылок.

03 · Поиск причины

Разбор конкретного отказа

Наблюдаемый симптом

CI отмечен зелёным, однако PDF не содержит изображений.

Диагностическая развилка

Проверьте предупреждения компиляции, реальные asset paths и PDF preview; один код завершения компилятора недостаточен.

Ограничение вывода: устанавливайте только то, что действительно следует из измерения; альтернативные причины остаются гипотезами до проверки. Типичная ошибка: Проверять PDF только по наличию в каталоге.

04 · Показ → практика

Протокол безопасного эксперимента

  1. Назовите оболочку, текущую среду и область воздействия. В рабочих репозиториях сначала изучите состояние без изменения данных.
  2. По первому примеру сформулируйте прогноз: какой вывод подтвердит выбранный механизм, а какой его опровергнет?
  3. Выполните одну разрешённую команду в подходящей среде. Сохраните реальный stdout/stderr и exit code.
  4. Сравните результат с трактовкой под code block, затем выполните отдельную независимую проверку. При расхождении остановитесь и исследуйте ошибку.
Safety gate: примеры с изменением файлов, контейнеров, БД, прав, сети или инфраструктуры выполняются только в изолированном учебном стенде с синтетическими данными. При риске потери данных: сначала dry run/backup/restore plan и явное согласование. Не отправляйте пароли, токены и личные данные.
05 · Самостоятельная работа

Новая задача без готового решения

Для синтетического пособия составьте трёхшаговый pipeline и критерий качества PDF помимо «файл существует».

Что сдавать

Выбранная Вами последовательность, прогноз, результат выполнения в синтетическом/читающем режиме, независимый контроль, указание возможного ложноположительного результата и безопасный способ восстановления (если было изменение).

06 · Контроль знаний

Вопросы, которые проверяют понимание

  1. Какие две разные сущности или стадии Вы должны различать в первом примере кода?
  2. Из симптома «CI отмечен зелёным, однако PDF не содержит изображений.» какие гипотезы возможны и какое наблюдение различит их?
  3. Почему проверять pdf только по наличию в каталоге — неверный диагностический вывод?
Показать критерий хорошего решения

Проверьте предупреждения компиляции, реальные asset paths и PDF preview; один код завершения компилятора недостаточен.

Нужны фактические доказательства, объяснение механизма, безопасная область воздействия и независимая проверка. Один зелёный тест не означает исправности всей системы.

L1 — воспроизводите готовое действие; L2 — решаете с опорой; L3 — сами выбираете способ для новой задачи, объясняете и проверяете; L4 — переносите навык и диагностируете риск/восстановление. Чтение учебника не присваивает уровень.
