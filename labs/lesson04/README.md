# Лабораторная 04 · WSL2, Linux, Docker: уровни системы

**Измеримая цель:** по фактическому выводу различить рабочую среду Windows/WSL, текущий каталог и домашний каталог Linux, наличие Docker CLI и доступность Docker Engine.

## Модель

Windows запускает WSL2-дистрибутив Ubuntu. Команды `pwd` и `cd` выполняются внутри Linux. `/mnt/c` указывает на файловую систему Windows; `/home/...` — обычно на файловую систему Linux. Docker CLI — клиент, который обращается к Docker Engine. Наличие CLI не означает, что Engine работает.

## Демонстрация преподавателя (образец)

В WSL команда `cat /etc/os-release` выводит сведения об Ubuntu. `pwd` может показать `/mnt/c/Users/...`, а `echo "$HOME"` — `/home/<user>`. Это разные пути по различным причинам: первый — текущий каталог, второй — домашний каталог. **Фактические значения зависят от среды.**

## Самостоятельная практика

1. Перед запуском предскажите, одинаковы ли `workdir` и `home` и почему.
2. Из корня локальной копии репозитория запустите `python3 labs/lesson04/environment.py`.
3. Зафиксируйте JSON-вывод. Проверьте `wsl_detected`, `docker_cli_available` и `docker_engine_version`.
4. Объясните, какие свойства вывод доказывает непосредственно и какие ещё требуют проверки.

**Возможные результаты:** `wsl_detected=false` означает, что скрипт не обнаружил признаки WSL — например, он запущен на обычном Linux. `docker_cli_available=false` означает отсутствие `docker` в PATH. `docker_engine_version=недоступен` при наличии CLI означает, что соединение с Engine в этот момент не подтверждено. `docker_engine_version=не проверялся` — клиента нет.

## Новая задача L3

Предположим, `docker --version` возвращает версию клиента, но `docker info` не может подключиться к движку. Независимо опишите два способа проверить гипотезу о неработающем Docker Desktop **без запуска/удаления контейнеров**; для каждого назовите ожидаемый вывод и условие успешной проверки. Не выполняйте потенциально разрушительные изменения.

## Критерии

- **L1:** запускает скрипт и находит Ubuntu.
- **L2:** правильно объясняет cwd/home, CLI/Engine по фактическому выводу.
- **L3:** самостоятельно диагностирует новый сбой с проверяемым выводом и границами вывода.
- **L4:** переносит на другую машину, сравнивает WSL/Windows и формирует безопасный план восстановления.

Откат не требуется: скрипт читает сведения; настройки не меняются. Запись в журнал должна содержать Ваш вывод и объяснение, а не только статус `PASS`.
