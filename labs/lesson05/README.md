# Лабораторная 05 · PID, права, RAM и swap

**Измеримая цель:** наблюдать свой процесс, прочитать владельца/права каталога и разделить *занятый swap*, *доступную память* и *текущий обмен страницами*.

## Механизмы

PID идентифицирует процесс в его пространстве имён; PPID — его родителя. UID/GID участвуют в проверках доступа. Для каталогов бит `x` даёт право прохода, `r` — чтение списка имён. `MemAvailable` — оценка ресурсов для новых приложений без активного использования swap. `pswpin` и `pswpout` — накопительные счётчики страниц в `/proc/vmstat`; **дельта между измерениями** информативнее абсолютной величины для текущей активности. На WSL2 память и счётчики относятся к Linux-среде, не обязательно ко всей Windows.

## Практика с постепенным снятием подсказок

1. Спрогнозируйте: должен ли PID программы совпадать с PPID? Может ли `Swap used > 0` при отсутствии обмена страницами в данную секунду?
2. Из корня репозитория запустите `python3 labs/lesson05/resources.py`.
3. Объясните каждое поле. Сравните `mem_available_mib` с `free -m`, а PID/PPID — с `ps` в **том же временном интервале**. Учтите, что кратковременный процесс может завершиться до запуска `ps`.
4. Повторите измерение позже и сравните дельты swap. Не запускайте нагрузочный тест ради получения ненулевых значений.

## Лабораторная ошибка (синтетика, без нагрузки)

Представьте: `available = 250 MiB`, `swap used = 3500 MiB`, `si=1000`, `so=1600` (KiB/s) в нескольких последовательных выборках. Сформулируйте гипотезу. Для подтверждения предложите новую независимую проверку. Почему одного `free` и одного ненулевого `swap used` недостаточно?

## Самостоятельная вариация L3

Есть два снимка: сервер A — `available = 120 MiB`, `swap used = 3000 MiB`, `si/so растут`; сервер B — `available = 6000 MiB`, `swap used = 3000 MiB`, `si=so=0`. Какой расследовать сначала? Обоснуйте, какие данные подтверждают предположение и какие причинные гипотезы пока нельзя доказать. Дополнительно укажите, почему `S` в `ps` не равно «завис».

## Критерии и безопасность

- **L1:** воспроизводит команду, находит PID и RAM.
- **L2:** объясняет RES/available/swap, сопоставляет измерения.
- **L3:** выбирает следующую диагностическую команду без подсказок, проверяет альтернативы и объясняет риск.
- **L4:** переносит диагностику на реальный тестовый контейнер с планом возврата в исходное состояние.

Скрипт выполняет только чтение `/proc` и `stat()`, не меняет права `chmod`, не посылает сигналы `kill`, не создаёт искусственную нехватку RAM. Откат не нужен.
