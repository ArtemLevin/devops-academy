# DEVOPS ACADEMY · проверяемые лабораторные стенды

Первая практическая серия (занятия **04–06**). Каждый стенд использует только стандартную библиотеку Python 3.10+, синтетические ответы или чтение локальных сведений. **Ни один стенд не изменяет настройки ОС, не запускает нагрузку, не удаляет файлы и не обращается к рабочим сервисам.**

## Начало работы

Откройте **Ubuntu в WSL2**, перейдите в каталог своей копии репозитория `devops-academy` и запускайте одну команду за раз. При первом получении проекта допускается `git clone https://github.com/ArtemLevin/devops-academy.git` в выбранном Вами учебном каталоге. Команда создаёт локальную копию, не изменяя удалённый репозиторий. Для обновления существующей копии сначала проверьте `git status` и не перезаписывайте свои изменения.

| Занятие | Исполняемое задание | Ожидаемое наблюдение |
|---|---|---|
| 04 — WSL2 и среда | `python3 labs/lesson04/environment.py` | Дистрибутив, WSL, cwd/home, UID; Docker CLI и Engine проверяются отдельно |
| 05 — Процессы, права, память | `python3 labs/lesson05/resources.py` | PID/PPID, права домашнего каталога, available/swap, изменение счётчиков за секунду |
| 06 — Сетевая диагностика | `python3 labs/lesson06/http_lab.py` | Локальные HTTP 200, 503, 404; `PASS` при соответствии ожиданиям |
| Автотесты кода стендов | `python3 -m unittest discover -s labs/tests -v` | Все тесты имеют `ok`; итог `OK` |

**Важно:** `PASS` означает, что тестовый код и синтетические ответы соответствуют ожидаемым. Он **не подтверждает L3 и не доказывает**, что реальные PostgreSQL, Redis или проектный веб-сервис исправны. L3 присваивается преподавателем после самостоятельной новой задачи и проверки фактических свидетельств.

## Формат свидетельств

Для каждого занятия сохраните текстом: цель → среда → прогноз до действия → команда → фактические stdout/stderr и exit code → интерпретация → независимая проверка → ограничения → план восстановления (если применим). **Не присылайте пароли, токены, персональные данные учеников или рабочие дампы.** Если вывод содержит персональные пути/имена хоста, допустимо их обезличить.

## Безопасность и выход из лаборатории

- 04: читает `/etc/os-release`, системные сведения и с ограничением времени выполняет `docker info`, если Docker CLI установлен. Никаких контейнеров не запускает.
- 05: читает `/proc/meminfo`, `/proc/vmstat` и права домашнего каталога; ожидает ~1 секунду. Не нагружает CPU/RAM и не выделяет swap намеренно.
- 06: создаёт временный HTTP-сервер исключительно на `127.0.0.1` со случайным портом, затем **закрывает его в `finally`**. Внешние подключения не нужны. Это учебный сервер, не предназначенный для production.
- Автотесты не требуют сети и внешних пакетов. GitHub Actions запускает их с `contents: read`; публикацию и деплой данный workflow **не осуществляет**.

## Почему именно такие упражнения

Мы отделяем механизмы от внешних зависимостей: диагностика WSL без поломки Windows, наблюдение за памятью без имитации OOM, ошибки HTTP без реального отказа PostgreSQL. Затем навык переносится на TutorBoard и Tutor Assistant Web после проверки актуального состояния их репозиториев и определения безопасной тестовой среды.
