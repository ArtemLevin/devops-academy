01

Архитектура веб-сервиса

Занятие 01 · клиент, сервер, HTTP и WebSocket

Клиент и сервер: кто инициирует обмен

Клиент — программа, отправляющая запрос или устанавливающая соединение с сервисом. Сервер — программа, принимающая запросы и формирующая ответы. В наших образовательных проектах клиентом часто выступает браузер, а серверную логику реализует веб-приложение.

Браузерклиент
→
HTTP-запросметод · URL · заголовки · тело
→
Веб-сервермаршрутизация · обработка
Браузерполучает результат
←
HTTP-ответстатус · заголовки · тело
←
Веб-приложениеподготовило ответ
Упрощённая модель одного HTTP-обмена. Реальная система может включать прокси, БД, очереди и балансировщик.

HTTP: запрос и ответ

HTTP — протокол прикладного уровня для обмена сообщениями между клиентом и сервером. Запрос содержит метод (например, GET), адрес ресурса, заголовки и при необходимости тело. Ответ содержит код статуса, заголовки и необязательное тело.

Ранее выполнено в Windows · запрос HEAD
curl.exe -I https://example.org

В учебной практике запрос вернул HTTP 200. Это подтвердило, что конкретный запрос успешно обработан по наблюдаемому HTTP-пути. Такой ответ не проверяет все страницы, базу данных, фоновые задания и долговременную надёжность сервиса.

200 OK Успешный ответ

Проверяем конкретный запрос, маршрут и обстоятельства, при которых он прошёл.

500 Ошибка обработки

Если ответ получен от приложения, это свидетельствует о сбое обработки, но не раскрывает первопричину.

WebSocket: двустороннее соединение

WebSocket позволяет клиенту и серверу обмениваться сообщениями по длительно живущему соединению. Он полезен для совместной доски, присутствия участников и обновлений в реальном времени. В типичном сценарии соединение устанавливается через процедуру HTTP Upgrade, после чего сообщения идут в обе стороны.

Ученикбраузер A
⇄
WebSocket-серверсообщения и состояние соединений
⇄
Преподавательбраузер B
Схематичный пример совместной работы. Какие именно события конкретный проект передаёт по WebSocket, необходимо проверять по актуальному коду.
Ограничение вывода
Работающая HTTP-страница не доказывает, что подключение WebSocket успешно; работающий WebSocket не доказывает, что изменения надёжно записываются в базу данных. Каждый участок пути нуждается в отдельной проверке.

Windows, WSL2 и Docker

Занятие 04 · состав среды и границы ответственности

WSL2 (Windows Subsystem for Linux 2) позволяет запускать дистрибутив Linux в Windows с использованием Linux-ядра в управляемой виртуализированной среде. Docker Desktop предоставляет Docker Engine и интеграцию с Windows/WSL2. Инструменты связаны, но отвечают за разные задачи.

Docker CLI и Docker Engine

Docker CLI — клиент командной строки. Docker Engine — служба, которая управляет образами и контейнерами. Наличие установленного клиента само по себе не гарантирует доступность Engine. Именно это мы наблюдали, когда первоначальный docker version сообщал об ошибке соединения с именованным каналом Docker Desktop.

Диагностическая логика
Если docker version показывает только Client и ошибку Server, сначала выясняют доступность Engine и контекст подключения. Если вывод показывает Client и Server, это подтверждает их взаимодействие в момент проверки. Запущенность PostgreSQL или Redis проверяется отдельно.

В каком терминале выполнять команды

Windows / PowerShell

wsl --list --verbose, docker version, docker compose version.

Ubuntu / Bash

pwd, ls, id, ps, top, free, vmstat.

В начале практики команда Get-Process была введена в CMD и не распознана: она относится к PowerShell. Это пример необходимости сначала установить тип командной оболочки, а затем выбирать её команды.

03

Файловая система и пути

От текущего каталога к абсолютному адресу объекта

Каталоги, корень и текущий путь

Файловая система Linux представляет каталоги и файлы в виде дерева с корнем /. Текущий рабочий каталог — контекст, относительно которого оболочка интерпретирует относительные пути. В Windows привычны пути вида C:\Users\...; в WSL этот диск обычно доступен как /mnt/c/Users/....

/ ├── etc/ │ └── os-release ← системные сведения ├── home/ │ └── timlevin/ ← домашний каталог ├── mnt/ │ └── c/ ← файловая система Windows C: ├── proc/ ← виртуальные сведения о процессах ├── root/ ← домашний каталог root └── usr/ ← программы и ресурсы

Три базовые команды

КомандаНазначениеЧто не делает

cd ~Переходит в домашний каталогНе перемещает файлы

Абсолютный и относительный пути

Абсолютный

/etc/os-release

Начинается с прямого слэша /. Выбор текущего каталога на него не влияет.

Относительный

etc/os-release

Разрешается от текущего каталога: из /home это был бы /home/etc/os-release.

. обозначает текущий каталог, .. — родительский каталог, ~ в Bash разворачивается в домашний каталог пользователя (в соответствующем контексте оболочки). В Linux разделитель пути — прямой слэш /, а не обратный \.

Реальное свидетельство · Ubuntu
$ cat /etc/os-release
PRETTY_NAME="Ubuntu 24.04.5 LTS"
VERSION_ID="24.04"
VERSION_CODENAME=noble
Разобранная ошибка
На заключительной проверке абсолютный путь сначала был назван относительным. Надёжный признак: начальный / означает поиск от корня; отсутствие такого символа обычно означает поиск относительно текущего каталога.

Пользователи и права доступа

Почему существуют Permission denied и кто может читать файл

Владелец, группа, остальные

Стандартные права Unix разделены на три категории субъектов: владелец (user), группа (group) и остальные (other). Для каждой категории задаются биты чтения r, записи w и выполнения/прохода x.

dобъект — каталог
rwxвладелец
r-xгруппа
---остальные
drwxr-x--- соответствует правам 750 для каталога: владелец 7, группа 5, остальные 0.
БитДля обычного файлаДля каталога
r (4)Читать содержимоеЧитать список имён
w (2)Изменять содержимоеИзменять записи каталога, обычно требуется и x
x (1)Запускать как программу при соответствующих условияхПроходить по пути и обращаться к известным именам внутри

Реальные объекты из Вашего терминала

Метаданные каталогов
drwxr-xr-x  root     root      /home
 drwxr-x--- timlevin timlevin /home/timlevin
 drwx------ root     root      /root

Важное наблюдение: ls /root вернул Permission denied, а ls -ld /root успешно показал права и владельца. Первая операция пыталась перечислить содержимое, вторая — получить метаданные самого каталога через разрешённый родительский путь.

UID, GID и группа sudo

Результат команды id · фрагмент
uid=1000(timlevin) gid=1000(timlevin)
groups=1000(timlevin),4(adm),24(cdrom),27(sudo),
       30(dip),46(plugdev),100(users)

Команда id определила пользователя и группы текущей сессии. Членство в sudo может позволять повышение полномочий согласно настройкам системы, однако обычный процесс Bash продолжает работать с пользовательской идентичностью, пока специально не повышены привилегии.

Порядок проверки стандартных битов

Сопоставить владельца файла с UID процесса

Если совпадают — применяются биты владельца.

Иначе сопоставить группу файла с группами процесса

При совпадении применяются групповые биты.

Если совпадений нет — использовать биты остальных

Также учитываются доступ к родительским каталогам, ACL и другие механизмы безопасности, если они задействованы.

Разобранная задача

drwxr-x--- root deploy /srv/app/data и -rw------- root root report.csv. Пользователь web входит в deploy.

Вывод: список каталога получить можно по групповым r-x; содержимое файла прочитать нельзя, поскольку у файла 600 и владелец root. После изменения файла на -rw-r----- root deploy чтение становится доступно группе deploy (при выполнении остальных условий доступа).

Безопасность
Для экспериментов с правами мы только читали метаданные. Команды изменения прав, владельцев и привилегий требуют отдельного плана и контекста: ошибка может нарушить работу сервисов или открыть доступ к данным.
05

Процессы Linux и их иерархия

PID, PPID, дерево предков, состояния R и S

Процесс — выполняющийся экземпляр программы со своим идентификатором и ресурсами. PID — идентификатор процесса, PPID — идентификатор родительского процесса. У процессов могут различаться пользователи, состояние и набор ресурсов.

Измерение собственной Bash
$ ps -p $$ -o pid,ppid,user,stat,comm
PID  PPID  USER      STAT  COMMAND
714  711   timlevin  Ss    bash

В Bash конструкция $$ обозначает PID текущей оболочки в рассматриваемом учебном контексте. Команда ps -p выбирает процесс, а -o задаёт нужные поля. USER=timlevin показывает, чьи полномочия имеет оболочка.

Дерево предков, подтверждённое двумя инструментами

systemd(1) └── init-systemd(Ub(2) └── SessionLeader(709) └── Relay(714)(711) └── bash(714) └── pstree(13400)

Сначала мы находили отдельные узлы цепочки с помощью ps, затем команда pstree -sp $$ показала дерево. Совпадение PID 709 → 711 → 714 стало независимой проверкой связей. Служебные имена в WSL2 могут отличаться между запусками; приведённые PID относятся к конкретной сессии.

Что означают состояния процессов

КодТехническое состояниеПрактическое значение
RRunning / runnableВыполняется либо готов к выполнению
SInterruptible sleepОжидает событие, может быть пробуждён
DUninterruptible sleepОжидание внутри ядра, часто ввод-вывод
TStoppedОстановлен исполнением/отладкой

Мы наблюдали bash со статусом Ss и systemd (PID 1, PPID 0) со статусом Ss. Это нормальная ситуация для процессов, ожидающих очередное событие. Состояние S само по себе не означает зависание.

Ограничение наблюдения
Сервис может находиться в состоянии ожидания и при этом нормально отвечать на запросы. Для оценки исправности необходимо проверить его поведение. Успешный ответ /health доказывает работу проверенного endpoint в момент запроса, но не обязательно всех workers, БД или очередей.

Как найти процесс с большим расходом RAM

В таблице top используется показатель RES — резидентная память процесса. VIRT включает всё виртуальное адресное пространство и не равен физическому потреблению RAM. Значения %MEM могут округляться, поэтому при небольших процессах полезно сравнивать RES.

Оперативная память, кеш и swap

Почему available и динамика si/so важны для диагностики

Как читать free

Измерение из Вашей Ubuntu · MiB
              total   used   free  shared  buff/cache  available
Mem:          15584    647  14792      27         365      14937
Swap:          4096      0   4096
14 937
MiB RAM available
647
MiB RAM used
0
MiB swap used

free — объём полностью свободной памяти. available — оценка того, сколько памяти можно предоставить приложениям без существенного обращения к swap, в том числе с учётом освобождаемой части кеша. Поэтому низкий free при большом available сам по себе не свидетельствует о проблеме.

Для Вашего измерения: 14 GiB = 14 336 MiB, а available = 14 937 MiB. Значит, исходный прогноз «меньше 14 GiB» не подтвердился: доступно примерно 14,59 GiB.

Swap: объём и активность

Swap — пространство, которое ядро может использовать для хранения вытесненных страниц памяти. Сам по себе занятый swap не доказывает текущий дефицит RAM: часть страниц могла быть вытеснена при более ранней нагрузке. Поэтому мы использовали vmstat для наблюдения за динамикой.

Интервальная диагностика · 4 выборки
vmstat 1 4
ПолеЧто показываетНаш результат
swpdОбъём занятых страниц в swap0
siСкорость загрузки данных из swap в память0 во всех 4 выборках
soСкорость записи данных из памяти в swap0 во всех 4 выборках
idДоля простоя CPU100% в округлённых показателях выборки

Первая строка vmstat обычно отражает средние величины с запуска системы для ряда показателей. Последующие строки относятся к заданным интервалам. Именно интервалам уделяют особое внимание при анализе текущей активности.

Для подтверждения причины смотрят на процессы, динамику, ограничения памяти и нагрузку приложения.

В учебной задаче Вы правильно выбрали сервер с available = 250 MiB и большим занятым swap как первый объект расследования. В другой задаче Вы заметили рост so, а затем стали учитывать si, swpd и wa. Рост wa может иметь несколько причин и отдельно не доказывает проблему swap.

Чего избегать
Не следует автоматически перезапускать сервер из-за одного низкого значения free или занятого swap. Сначала нужны временные ряды и признаки воздействия на приложение: задержки, ошибки, завершение процессов, ограничения контейнеров, показания ядра.
08

Инженерный метод диагностики

Воспроизводимый вывод вместо поспешного решения

На всех занятиях мы возвращались к одному циклу: гипотеза → безопасная проверка → наблюдение → вывод → следующая проверка. В этом цикле принципиально важно отделять факты от интерпретаций.

Зафиксировать симптом

Например: «Пользователь видит таймаут при открытии доски»; установить время, маршрут, частоту и затронутые операции.

Сформулировать проверяемые гипотезы

DNS, соединение, HTTP-обработчик, WebSocket, база данных, ресурсы процесса. Выбрать конкретную часть пути.

Выбрать наименее рискованный диагностический шаг

Чтение метаданных, запрос состояния, просмотр статистики. Не изменять продакшен без разрешения и плана.

Записать фактическое наблюдение

Полный вывод команды, отметка времени, адрес назначения, код состояния, интервалы измерения.

Разделить подтверждённое и неизвестное

HTTP 200 подтверждает успешный конкретный ответ; S не доказывает зависание; ls -ld не доказывает чтение содержимого.

Проверить независимым методом и оформить вывод

Например, для RAM сопоставить top, free и vmstat. Зафиксировать ограничения измерения.

Задачи с развёрнутым ответом

Задача А · Почему ls -ld /root сработала, а ls /root — нет?

ls /root пытается перечислить содержимое каталога; для этого необходимы соответствующие права. ls -ld /root получает метаданные самого объекта через доступный родительский путь. У /root права 700, поэтому обычный пользователь не может читать его список имён.

Задача Б · Как отличить процесс, который ждёт работу, от сервиса, который перестал её выполнять?

Состояние S само по себе недостаточно. Нужно проверить предусмотренное поведение: запрос к HTTP-обработчику, время ответа, ошибки, выполнение фоновой задачи или иную операцию с известным ожидаемым результатом. Затем уточнить, какие именно компоненты затронула проверка.

Задача В · Почему рост si и so вместе с малым available настораживает?

Памяти, которую система оценивает как доступную, мало; страницы активно перемещаются между RAM и swap. Это согласуется с гипотезой memory pressure. Для вывода о первопричине необходимо дополнительно исследовать процессы, временную динамику и ограничения среды.

Задача Г · Что означает совпадение родительской цепочки в ps и pstree?

Два разных представления согласуются по PID и PPID: это повышает уверенность в реконструированной иерархии на момент наблюдений. Совпадение не сообщает само по себе, исправны ли процессы или какие операции они выполняют.
