Занятие 04 · Воспроизводимая проверка

Лабораторная 04: где работает моя команда?

Механизм. Установка WSL2 означает запуск Linux-среды под Windows. Текущий путь (pwd) и домашний путь пользователя могут различаться. Клиент Docker и сервер Docker Engine также представляют разные компоненты.

  1. Прогноз: совпадут ли значения workdir и home? Будет ли доступен Docker Engine?
  2. Действие:
    python3 labs/lesson04/environment.py
    Сохраните JSON и реальный код возврата.
  3. Проверка: сравните сведения об ОС с /etc/os-release, а вывод о Docker — с независимой проверкой клиента и движка.
  4. Перенос: придумайте план диагностики ситуации «Docker CLI работает, но Engine недоступен». Зафиксируйте два безопасных доказательства.
Возможный результат и критерии оценки

На Ubuntu в WSL2 ожидаются признаки wsl_detected=true, имя дистрибутива и различные значения home/workdir (если Вы пришли из файлов Windows). Docker CLI может отсутствовать, а Engine — быть недоступен. Точное состояние определяется фактическим запуском. Уровень L2 — корректно объяснить значения; L3 — самостоятельно проверить новый сбой.

Занятие 05 · Измерение во времени

Лабораторная 05: процесс, права, memory pressure

Механизм. PID/PPID описывают связи процессов. Права домашнего каталога задают возможности обращения к файлам. MemAvailable оценивает доступную память, а значения pswpin/pswpout являются накопительными; текущую активность отражает их разность за интервал.

  1. Прогноз: может ли swap быть занят при нулевых дельтах его чтения/записи?
  2. Действие:
    python3 labs/lesson05/resources.py
    Значения получены чтением /proc; ненулевая активность намеренно не создаётся.
  3. Проверка: сравните mem_available_mib с данными free и поясните различие между RSS, available и занятым swap.
  4. Перенос: изучите два синтетических сервера: available=120 MiB с ростом si/so и available=6000 MiB при отсутствии обмена страницами. Где выше приоритет проверки?
Возможный результат и критерии оценки

Ожидается JSON с PID, PPID, правами и памятью. Нулевые дельты swap_in_pages_delta/swap_out_pages_delta при занятом swap возможны. L3: самостоятельно выбрать независимый инструмент, проверить гипотезу и назвать ограничения измерения.

Занятие 06 · Синтетическая неисправность

Лабораторная 06: когда HTTP отвечает ошибкой

Механизм. DNS, TCP и HTTP — последовательные этапы, каждый из которых может отказать независимо. Если получен HTTP 503, сервер уже обработал сетевое соединение и сформировал HTTP-ответ. Это не доказывает исправность приложения, но помогает локализовать отказ.

  1. Прогноз: запишите ожидаемые коды для /health, /dependency и /missing.
  2. Действие:
    python3 labs/lesson06/http_lab.py
    Сервер работает только на loopback-адресе с автоматически выбранным портом и закрывается после проб.
  3. Проверка: получите 200, 503 и 404. Убедитесь, что программа напечатала PASS и вернула приглашение оболочки.
  4. Перенос: пусть /health отдаёт 200, а /api/reports — 503. Назовите три гипотезы, минимальные безопасные проверки и ограничения диагноза.
Эталонные ответы — раскрывайте после прогноза
GET /health     → HTTP 200
GET /dependency → HTTP 503
GET /missing    → HTTP 404
PASS: ...

HTTP 503 — синтетический отказ зависимости, 404 — отсутствующий маршрут. Оба означают, что ответ HTTP был получен. Никаких настоящих баз данных скрипт не запускает.

Автоматическая проверка

Тесты демонстрационных стендов

Запустите тесты из корня локального репозитория:

python3 -m unittest discover -s labs/tests -v

Пять тестов проверяют разбор /etc/os-release, разбор метрик Linux и работу локального HTTP-сервера. В репозитории добавлен workflow GitHub Actions для повторяемого запуска на push/PR. Отсутствие отчёта Actions означает, что удалённый запуск CI ещё не подтверждён.

Матрица подтверждения навыка

L1: запускает команду. L2: объясняет фактические поля вывода и назначение команд. L3: самостоятельно решает новую задачу, выбирает проверку и интерпретирует наблюдения. L4: переносит навык в другой контекст и управляет рисками.
